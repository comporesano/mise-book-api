# MISE Booking API

REST API для онлайн-бронирования столиков в ресторане - тестовое задание для позиции **Backend Trainee (Python / FastAPI)** в MISE.

Сервис умеет создавать бронь, отдавать список броней с фильтром по дате, находить бронь по id и отменять её. Отмена - мягкая: запись не удаляется, а переводится в статус `cancelled`.

## Стек

| Технология | Зачем |
|---|---|
| Python 3.11+ | язык |
| uv | менеджер зависимостей и виртуального окружения |
| FastAPI | роутинг, зависимости, обработка ошибок, авто-документация |
| Pydantic v2 | схемы запросов/ответов и валидация полей |
| SQLAlchemy 2.0 (async) + PostgreSQL | хранение данных, БД поднимается одной командой через docker-compose |
| Alembic | версионирование схемы БД (миграции) |
| Uvicorn | ASGI-сервер |
| pytest + httpx | тесты эндпоинтов |

## Эндпоинты

| Метод | Путь | Описание | Успешный ответ |
|---|---|---|---|
| `POST` | `/api/v1/bookings` | Создать бронь | `201` - объект брони со статусом `active` |
| `GET` | `/api/v1/bookings` | Список броней, опциональный фильтр `?date=YYYY-MM-DD` | `200` - список броней |
| `GET` | `/api/v1/bookings/{id}` | Получить бронь по id | `200` - объект брони |
| `DELETE` | `/api/v1/bookings/{id}` | Отменить бронь | `200` - объект брони со статусом `cancelled` |

## Формат ответов

Успешные ответы приходят в обёртке: `status`, `message`, `data` (полезная нагрузка) и `status_code`. Объект брони лежит в `data`:

```json
{
  "status": "success",
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Иван Петров",
    "phone": "+79991234567",
    "booking_date": "2026-09-20",
    "booking_time": "19:00",
    "guests": 4,
    "status": "active"
  },
  "status_code": 201
}
```

Бизнес-ошибки возвращаются в формате `{"detail": "..."}`.

## Валидация

| Поле | Правило |
|---|---|
| `name` | минимум 2 символа; только буквы, пробелы и дефис |
| `phone` | российский формат: `+7XXXXXXXXXX` или `8XXXXXXXXXX` (10 цифр после кода) |
| `booking_date` | не раньше сегодняшнего дня, не позже чем +90 дней |
| `booking_time` | только слоты с 12:00 до 22:00 с шагом в час |
| `guests` | целое число от 1 до 12 |

## Ошибки

| Код | Случай | Формат |
|---|---|---|
| `201` | бронь создана | объект брони со статусом `active` |
| `422` | невалидные входные данные | стандартный ответ FastAPI / Pydantic |
| `404` | бронь с указанным id не найдена | `{"detail": "Booking not found"}` |
| `409` | слот на выбранные дату/время уже занят | `{"detail": "..."}` |
| `200` | успешная отмена | объект брони со статусом `cancelled` |

Ошибки валидации возвращаются в стандартном формате FastAPI, бизнес-ошибки - в формате `{"detail": "..."}`.

## Запуск

### Локально

```bash
uv sync                          # создаст .venv и установит зависимости
cp .env.example .env             # при необходимости поправьте настройки
docker compose up -d db          # PostgreSQL (или используйте свой локальный сервер)
uv run uvicorn app.main:app --reload
```

Документация доступна сразу после старта:

- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc

### Docker

```bash
docker compose up --build
```

Поднимет оба сервиса: API на http://127.0.0.1:8000, PostgreSQL на порту 5432.
Контейнер API перед стартом сам применяет миграции (`alembic upgrade head`).

## Миграции

Схема БД версионируется через Alembic. После изменения моделей:

```bash
uv run alembic revision --autogenerate -m "описание изменения"
uv run alembic upgrade head
```

## Тесты

Перед запуском поднимите базу: `docker compose up -d db`. Затем:

```bash
uv run pytest -v
```

## Примеры запросов

```bash
# Создать бронь
curl -X POST http://127.0.0.1:8000/api/v1/bookings \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Иван Петров",
    "phone": "+79991234567",
    "booking_date": "2026-09-20",
    "booking_time": "19:00",
    "guests": 4
  }'

# Список броней на конкретную дату
curl "http://127.0.0.1:8000/api/v1/bookings?date=2026-09-20"

# Получить бронь по id
curl http://127.0.0.1:8000/api/v1/bookings/1

# Отменить бронь
curl -X DELETE http://127.0.0.1:8000/api/v1/bookings/1
```

## Ключевые решения

- **uv вместо pip** - зависимости и версии зафиксированы в `pyproject.toml` + `uv.lock`, окружение воспроизводится одной командой `uv sync`.
- **PostgreSQL через SQLAlchemy 2.0 (async) + asyncpg** - как в боевом проекте; БД поднимается одной командой `docker compose up -d db`, данные хранятся в named-volume.
- **Слои «роуты → репозитории → модели»** - роуты остаются тонкими, бизнес-правила (проверка слота, мягкая отмена) живут в репозитории, поэтому их легко тестировать отдельно от HTTP.
- **Проверка занятости слота (409)** - слоты строго почасовые, поэтому конфликт - это существующая активная бронь на ту же дату и то же время.
- **Отмена без удаления** - `DELETE` переводит бронь в `cancelled`, история не теряется.
- **Alembic для миграций** - схема БД версионируется: `uv run alembic revision --autogenerate` генерирует миграцию из моделей, `uv run alembic upgrade head` применяет её.
- **Версия API и обёртка ответов** - эндпоинты живут под `/api/v1`; успешные ответы в обёртке `{status, message, data, status_code}`, бизнес-ошибки в формате `{"detail": "..."}`.
- **Тесты** - 20 тестов через httpx.AsyncClient покрывают весь контракт API: 201/422/404/409/200, фильтр по дате, отмену и освобождение слота.
